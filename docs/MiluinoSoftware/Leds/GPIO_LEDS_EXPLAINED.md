# GPIO и светодиоды К1986ВЕ92FI: пояснения к коду

Документ объединяет пояснения к учебному примеру управления светодиодами через регистры. Примеры соответствуют текущим файлам `main.c`, `main.h`, `leds.c`, `leds.h`, `gpio.h` и `registers.h`.

## 1. Что делает программа

Программа настраивает GPIO четырёх светодиодов, после чего попеременно включает и выключает HL2. Между переключениями выполняется приблизительная программная задержка.

```c
leds_gpio_init();

while (1)
{
	led_on(LED2);
	delay_loop(BLINK_DELAY_ITERATIONS);

	led_off(LED2);
	delay_loop(BLINK_DELAY_ITERATIONS);
}
```

Периферия настраивается непосредственно через регистры: библиотечные функции настройки GPIO не вызываются. Стандартный заголовок `<stdint.h>` предоставляет типы целых чисел заданной ширины, в частности `uint32_t`; его подключение не добавляет драйвер GPIO.

## 2. Распределение кода по файлам

| Файл | Назначение |
| --- | --- |
| `main.c` | Функция `main()`, цикл мигания, программная задержка и её настройка |
| `main.h` | Общие подключения приложения; сейчас подключает `<stdint.h>` и `leds.h` |
| `registers.h` | Общий макрос `REG32` для доступа к аппаратным регистрам |
| `gpio.h` | Адреса регистров GPIO и биты разрешения тактирования используемых портов |
| `leds.h` | Распиновка светодиодов, маски, перечисление `led_t` и прототипы функций |
| `leds.c` | Реализации инициализации, включения и выключения светодиодов |

`main.c` подключает `main.h`, а через него получает объявления из `leds.h`. Файл `leds.c` подключает собственный заголовок `leds.h` и заголовок регистров `gpio.h`. Заголовок `gpio.h` подключает `registers.h`.

Заголовок сообщает другим единицам трансляции необходимые типы, константы и объявления функций. Реализация функции находится в `.c`-файле. Подключать `leds.c` через `#include` не требуется: он компилируется отдельно.

### Защита заголовков от повторного включения

```c
#ifndef REGISTERS_H
#define REGISTERS_H

/* Содержимое заголовка. */

#endif /* REGISTERS_H */
```

При первом подключении определяется макрос `REGISTERS_H`. При повторном подключении условие `#ifndef` уже не выполняется, и содержимое заголовка повторно не обрабатывается.

### Разделители и поясняющие комментарии

Названия разделов записаны на английском: `Includes`, `Defines`, `Registers`, `Types`, `Function prototypes`, `Functions`, `Private defines`. Поясняющие комментарии и описание функций остаются на русском языке. Разделители служат только для чтения исходного текста и не влияют на выполнение программы.

## 3. Подключение светодиодов

Используется распиновка существующей платы по схеме ДФТВ.434519.003Э3, лист 1.

| Светодиод | Порт и вывод | Физический вывод МК | Токоограничивающий резистор | Активный уровень |
| --- | --- | --- | --- | --- |
| HL1 | PC2 | 40 | R6 | Высокий |
| HL2 | PA3 | 60 | R7 | Высокий |
| HL3 | PA5 | 58 | R8 | Высокий |
| HL4 | PA1 | 62 | R9 | Высокий |

Пример цепи HL2:

```text
PA3 -> R7 -> анод HL2 -> катод HL2 -> GND
```

Высокий уровень на PA3 создаёт ток через резистор и светодиод; HL2 загорается. При низком уровне HL2 погашен. Резистор ограничивает ток. Для PA3 допустимый выходной ток по модулю составляет до 6 мА; точный ток светодиода зависит от напряжения на выходе, прямого падения напряжения на LED и сопротивления резистора.

PA1, управляющий HL4, на этой плате соединён с PF0. Поэтому `led_4_gpio_init()` оставляет PF0 входом GPIO, а выходной сигнал формирует через PA1. Для этого добавлены отдельные маски `LED4_PF0_*` и определения регистров PORTF.

Распиновка относится именно к указанной схеме. Для другой ревизии платы её необходимо сверять отдельно.

## 4. Что такое аппаратный регистр

Регистр периферии доступен по определённому адресу в адресном пространстве процессора. Чтение и запись по этому адресу обращаются к аппаратному блоку. Например, запись в GPIO может изменить напряжение на ножке микроконтроллера.

Адрес регистра получается из базового адреса блока и смещения нужного регистра:

```text
адрес регистра = базовый адрес блока + смещение
```

Для PORTA:

```c
#define PORTA_BASE  0x400A8000UL
#define PORTA_RXTX  REG32(PORTA_BASE + 0x00UL)
#define PORTA_OE    REG32(PORTA_BASE + 0x04UL)
```

Следовательно, `RXTX` находится по адресу `0x400A8000`, а `OE` — по адресу `0x400A8004`.

Хотя GPIO-порты логически содержат до 16 линий, доступ к рассматриваемым регистрам выполняется как к 32-битным значениям. Некоторые регистры используют по два бита на каждый вывод.

## 5. Что делает REG32 и обязателен ли он

В `registers.h` определён макрос:

```c
#define REG32(address) (*(volatile uint32_t *)(address))
```

`REG32` — не тип данных и не функция. Это макрос препроцессора: перед компиляцией его использование заменяется соответствующим выражением.

Он сокращает повторяющуюся запись. Без него допустимо определить регистр непосредственно:

```c
#define PORTA_RXTX (*(volatile uint32_t *)0x400A8000UL)
```

Оба варианта дают одинаковый способ обращения к регистру. В примере общий макрос вынесен в `registers.h`, чтобы его могли использовать будущие модули другой периферии.

### Как раскрывается макрос

```c
#define RST_CLK_BASE       0x40020000UL
#define RST_CLK_PER_CLOCK  REG32(RST_CLK_BASE + 0x1CUL)
#define PER_CLOCK_PORTA_EN (1UL << 21U)
```

Строка:

```c
RST_CLK_PER_CLOCK |= PER_CLOCK_PORTA_EN;
```

после раскрытия макросов соответствует выражению:

```c
(*(volatile uint32_t *)(0x40020000UL + 0x1CUL)) |= (1UL << 21U);
```

Последовательность разбора:

1. `0x40020000UL + 0x1CUL` задаёт адрес регистра `PER_CLOCK`.
2. `(volatile uint32_t *)` преобразует адрес в указатель на 32-битное значение.
3. `*` разыменовывает указатель и позволяет обращаться к значению регистра.
4. `|=` устанавливает нужный бит, сохраняя остальные биты прочитанного значения.

Дополнительное разыменование перед `RST_CLK_PER_CLOCK` не требуется: оно уже находится внутри `REG32`.

### Чем отличается макрос указателя

Если определить именно указатель:

```c
#define RST_CLK_PER_CLOCK_PTR ((volatile uint32_t *)0x4002001CUL)
```

то разыменование потребуется при использовании:

```c
*RST_CLK_PER_CLOCK_PTR |= PER_CLOCK_PORTA_EN;
```

В текущем варианте `RST_CLK_PER_CLOCK` обозначает уже разыменованный регистр, доступный для чтения и записи.

### Когда происходит обращение к оборудованию

Само объявление `#define` ничего не читает и не записывает. Действие определяется тем, как используется выражение:

```c
uint32_t value = PORTA_RXTX; /* Чтение регистра. */
PORTA_RXTX = LED2_MASK;      /* Запись значения в регистр целиком. */
PORTA_RXTX |= LED2_MASK;     /* Чтение, изменение и запись регистра. */
```

Прямая запись через `=` задаёт значение всего регистра, поэтому её нельзя считать равнозначной установке одного бита через `|=`.

## 6. Зачем нужен volatile

В выражении:

```c
(volatile uint32_t *)
```

`volatile` относится к значению по адресу, а не к самому числовому адресу. Получается указатель на 32-битный объект, обращения к которому компилятор должен сохранять согласно правилам для `volatile`.

Аппаратный регистр отличается от обычной переменной: его значение может меняться из-за работы оборудования, а запись может иметь физический эффект независимо от последующего чтения программой.

Без `volatile` компилятор может применить оптимизации обычной памяти: использовать сохранённое значение вместо повторного чтения, удалить запись как ненужную или объединить записи. Для аппаратных регистров такие преобразования могут изменить требуемое поведение.

Объяснение для занятия:

> Регистр выглядит для программы как ячейка памяти, но связан с оборудованием. `volatile` сообщает компилятору, что обращения к этой ячейке имеют значение и должны сохраняться.

Для примера можно обсудить кнопку: её состояние может измениться между двумя чтениями без какой-либо записи со стороны программы.

### Почему volatile не видно в вызовах STM32 SPL

В заголовках CMSIS используется макрос:

```c
#define __IO volatile
```

Поля структуры регистров объявляются с ним:

```c
__IO uint32_t ODR;
```

После раскрытия макроса это:

```c
volatile uint32_t ODR;
```

Поэтому при обращении `GPIOA->ODR` квалификатор уже содержится в объявлении поля, и повторять его в каждой строке не требуется. В нашем примере структур регистров нет, поэтому квалификатор указан внутри `REG32`.

## 7. Номер вывода и битовая маска

```c
#define LED2_PIN  3U
#define LED2_MASK (1UL << LED2_PIN)
```

`LED2_PIN` — номер линии PA3 внутри порта, а не номер физического вывода корпуса. `LED2_MASK` — число, в котором установлен только соответствующий бит.

```text
1 << 3 = 0000 1000 = 0x08
```

Нумерация битов начинается с нуля. Бит 3 — четвёртый справа. Суффикс `U` означает беззнаковую целую константу, а `UL` — беззнаковую константу типа `unsigned long`; в используемом ARMCC этот тип имеет ширину 32 бита.

### Установка и сброс бита

```c
PORTA_RXTX |= LED2_MASK;  /* Установить бит 3. */
PORTA_RXTX &= ~LED2_MASK; /* Сбросить бит 3. */
```

`|` — побитовое ИЛИ: единицы маски устанавливают соответствующие биты. `~` инвертирует маску. При побитовом И `&` ноль в маске очищает соответствующий бит, а единица сохраняет прочитанное значение этого бита.

Например, в пределах младшего байта:

```text
LED2_MASK  = 0000 1000
~LED2_MASK = 1111 0111
```

Для операций с регистрами используются побитовые `|` и `&`, а не логические `||` и `&&`.

## 8. Что означает рисунок внутреннего устройства вывода

Рисунок 30 на странице 202 спецификации показывает внутреннее устройство одного вывода микроконтроллера. Справа расположен физический контакт `PAD`, слева — внутренние сигналы и управляющие настройки.

### Выходной тракт

```text
Port_TX / Main_TX / Alter_TX / Remap_TX -> MUX -> TX -> PAD
```

| Обозначение | Значение |
| --- | --- |
| `PAD` справа | Физический контакт микросхемы |
| `Port_TX` | Значение GPIO, записанное программой в `RXTX` |
| `Main_TX` | Сигнал основной функции периферии |
| `Alter_TX` | Сигнал альтернативной функции периферии |
| `Remap_TX` | Сигнал переопределённой функции периферии |
| `MUX` | Мультиплексор: выбирает один из источников |
| `Port_Func[1:0]` | Два бита регистра `FUNC`, управляющие выбором источника |
| `TX` | Выходной драйвер, формирующий электрический уровень |
| `Port_OE` | Разрешение выхода от регистра `OE` в режиме GPIO |
| `Main_OE`, `Alter_OE`, `Remap_OE` | Разрешение выхода от соответствующих периферийных функций |

Верхний мультиплексор выбирает данные для выдачи на ножку. Нижний мультиплексор выбирает, кто разрешает работу выходного драйвера. При `FUNC = 00` управление данными и направлением берётся от GPIO.

### Входной тракт и дополнительные элементы

```text
PAD -> RX -> чтение состояния вывода
```

| Обозначение | Значение |
| --- | --- |
| `RX` | Цифровой входной приёмник, определяющий логический уровень на выводе |
| `Analog`, `EN` | Управление разрешением работы цифровой части вывода |
| `To Analog` | Соединения с аналоговыми блоками, доступными на конкретном выводе |
| `PULL UP` | Подтяжка к питанию через внутренний резистор |
| `PULL DOWN` | Подтяжка к земле через внутренний резистор |
| `PD`, `MODE` | Настройки режима выходного драйвера и входного приёмника |
| `GFEN` | Входной фильтр коротких импульсов |
| `ESD R`, защитные диоды | Элементы защиты вывода от электростатических разрядов |

Регистр `PWR` отдельно на рисунке не обозначен, но его настройка также необходима для работы передатчика.

## 9. Зачем включать тактирование порта

После включения питания тактирование большинства периферийных блоков отключено. Перед настройкой GPIO нужно подать тактовый сигнал на соответствующий порт.

```c
RST_CLK_PER_CLOCK |= PER_CLOCK_PORTA_EN;
```

Регистр `PER_CLOCK` расположен по адресу `0x4002001C`. Номера битов разрешения тактирования:

| Порт | Бит |
| --- | --- |
| PORTA | 21 |
| PORTC | 23 |
| PORTF | 29 |

Используется `|=`, чтобы включить нужный порт и сохранить остальные биты регистра. Например, тактирование самого блока `RST_CLK` после сброса уже разрешено битом 4.

В примере частота ядра специально не перенастраивается. При первоначальном запуске МК использует HSI с типовой частотой 8 МГц, если последующий стартовый код её не изменяет.

## 10. Назначение регистров GPIO

| Регистр | Смещение | Для чего используется |
| --- | --- | --- |
| `RXTX` | `0x00` | Данные для выдачи и чтение состояния выводов |
| `OE` | `0x04` | Направление GPIO: 0 — вход, 1 — выход |
| `FUNC` | `0x08` | Выбор GPIO или периферийной функции |
| `ANALOG` | `0x0C` | Выбор аналогового или цифрового режима |
| `PULL` | `0x10` | Внутренние подтяжки к земле и питанию |
| `PD` | `0x14` | Режим выходного драйвера и гистерезис входа |
| `PWR` | `0x18` | Разрешение передатчика и скорость фронта |
| `GFEN` | `0x1C` | Входной фильтр; в текущем примере не используется |

Наличие строки в таблице не означает, что соответствующий макрос уже добавлен в `gpio.h`: сейчас определены только нужные для примера регистры.

### RXTX: значение на выводе

Если PA3 настроен как цифровой выход GPIO, бит 3 регистра `RXTX` задаёт его логический уровень:

- 1 — высокий уровень, примерно напряжение питания; HL2 включён.
- 0 — низкий уровень, примерно 0 В; HL2 выключен.

Для чтения GPIO также используется `RXTX`. Согласно описанию МК, биты выводов в аналоговом режиме читаются как единицы, поэтому такое чтение нельзя трактовать как обычное чтение цифрового входа.

### OE: направление

```c
PORTA_OE &= ~LED2_MASK; /* Выключить выходной драйвер на время настройки. */
PORTA_OE |= LED2_MASK;  /* Разрешить выдачу сигнала на PA3. */
```

Когда выходной драйвер отключён, уровень на ножке может определяться внешней цепью и подтяжками.

### FUNC: кто управляет выводом

В `FUNC` каждому выводу выделено два бита:

| Значение поля | Режим |
| --- | --- |
| `00` | GPIO |
| `01` | Основная функция |
| `10` | Альтернативная функция |
| `11` | Переопределённая функция |

Для PA3 поле расположено в битах `[7:6]`. Выбор GPIO выполняется очисткой обоих битов:

```c
PORTA_FUNC &= ~LED2_FIELD_MASK;
```

### ANALOG: зачем устанавливать единицу

```c
PORTA_ANALOG |= LED2_MASK;
```

У этого МК значение бита `ANALOG` трактуется так:

- 0 — аналоговый режим.
- 1 — цифровой режим.

Несмотря на название регистра, единица включает именно цифровой режим. После сброса регистр равен нулю. Одних настроек `OE` и `RXTX` недостаточно: для обычного цифрового выхода требуется также выбрать цифровой режим и включить передатчик через `PWR`.

Эти настройки отвечают на разные вопросы:

```c
PORTA_ANALOG |= LED2_MASK; /* Использовать цифровой режим. */
PORTA_OE |= LED2_MASK;     /* Направление — выход. */
PORTA_RXTX |= LED2_MASK;   /* Выдать высокий уровень. */
```

### PULL: две независимые подтяжки

В регистре `PULL` находятся две группы битов:

| Биты регистра | Назначение |
| --- | --- |
| `[15:0]` | Подтяжки вниз, к земле |
| `[31:16]` | Подтяжки вверх, к питанию |

Для PA3 подтяжка вниз управляется битом 3, а подтяжка вверх — битом 19, то есть `16 + 3`.

Вместо общей маски используются два отдельных определения:

```c
#define LED2_PULL_DOWN_MASK LED2_MASK
#define LED2_PULL_UP_MASK   (LED2_MASK << 16U)
```

Отключение выполняется явно двумя строками:

```c
PORTA_PULL &= ~LED2_PULL_DOWN_MASK;
PORTA_PULL &= ~LED2_PULL_UP_MASK;
```

Для светодиода, управляемого обычным выходным драйвером, внутренние подтяжки не нужны. Их отключение задаёт явную конфигурацию вывода.

### PD: обычный выходной драйвер

```c
PORTA_PD &= ~LED2_MASK;
```

В младшей половине `PD` ноль выбирает управляемый драйвер, способный формировать высокий и низкий уровни; такой режим также называют push-pull. Единица выбирает открытый сток. Для нашего включения светодиодов используется ноль.

Старшая половина `PD` задаёт гистерезис входного приёмника. Приведённая строка изменяет только бит режима выхода PA3.

## 11. Двухбитные поля и настройка PWR

```c
#define LED2_FIELD_SHIFT (2U * LED2_PIN)
#define LED2_FIELD_MASK  (3UL << LED2_FIELD_SHIFT)
#define LED2_PWR_SLOW    (1UL << LED2_FIELD_SHIFT)
```

Для каждого вывода в регистрах `FUNC` и `PWR` выделено два бита. Поэтому для линии с номером `n` начало поля находится на позиции `2 * n`.

Для PA3:

```text
LED2_PIN         = 3
LED2_FIELD_SHIFT = 6
LED2_FIELD_MASK  = 0x000000C0  (11 в битах [7:6])
LED2_PWR_SLOW    = 0x00000040  (01 в битах [7:6])
```

| Светодиод | Поле `FUNC` и `PWR` | Маска поля | Значение для медленного фронта |
| --- | --- | --- | --- |
| HL1 / PC2 | `[5:4]` | `0x00000030` | `0x00000010` |
| HL2 / PA3 | `[7:6]` | `0x000000C0` | `0x00000040` |
| HL3 / PA5 | `[11:10]` | `0x00000C00` | `0x00000400` |
| HL4 / PA1 | `[3:2]` | `0x0000000C` | `0x00000004` |

### Значения поля PWR

| Значение | Режим |
| --- | --- |
| `00` | Передатчик отключён |
| `01` | Медленный фронт, порядка 100 нс |
| `10` | Быстрый фронт, порядка 20 нс |
| `11` | Максимально быстрый фронт, порядка 10 нс |

Фронт — это переход напряжения между логическими уровнями. Эта настройка не задаёт частоту мигания, яркость светодиода или непосредственно величину выходного тока. Для медленного переключения светодиода достаточно значения `01`.

### Разбор строки настройки

```c
PORTA_PWR = (PORTA_PWR & ~LED2_FIELD_MASK) | LED2_PWR_SLOW;
```

1. `PORTA_PWR & ~LED2_FIELD_MASK` очищает биты `[7:6]`, сохраняя остальные биты прочитанного значения.
2. `| LED2_PWR_SLOW` записывает в очищенное поле значение `01`.
3. Присваивание сохраняет получившееся значение в регистр.

Смысл выражения: установить `PWR3 = 01`, сохранив настройки остальных выводов.

Просто `PORTA_PWR |= LED2_PWR_SLOW` не гарантирует нужную конфигурацию: если раньше поле содержало `10`, результатом будет `11`. Поэтому сначала очищается всё поле, затем записывается новое значение.

## 12. Порядок инициализации светодиода

Полная настройка HL2 в текущем коде:

```c
void led_2_gpio_init(void)
{
	RST_CLK_PER_CLOCK |= PER_CLOCK_PORTA_EN;

	PORTA_OE &= ~LED2_MASK;

	PORTA_FUNC &= ~LED2_FIELD_MASK;
	PORTA_ANALOG |= LED2_MASK;
	PORTA_PULL &= ~LED2_PULL_DOWN_MASK;
	PORTA_PULL &= ~LED2_PULL_UP_MASK;
	PORTA_PD &= ~LED2_MASK;
	PORTA_PWR = (PORTA_PWR & ~LED2_FIELD_MASK) | LED2_PWR_SLOW;

	PORTA_RXTX &= ~LED2_MASK;
	PORTA_OE |= LED2_MASK;
}
```

Порядок действий:

1. Включить тактирование PORTA.
2. Отключить выходной драйвер PA3 на время изменения настроек.
3. Выбрать GPIO в `FUNC`.
4. Включить цифровой режим в `ANALOG`.
5. Отключить подтяжку вниз и подтяжку вверх.
6. Выбрать обычный выходной драйвер в `PD`.
7. Включить передатчик с медленным фронтом через `PWR`.
8. Заранее задать низкий уровень, чтобы светодиод был погашен.
9. Разрешить выход через `OE`.

Настройка начального уровня перед разрешением выхода позволяет начать с определённого состояния светодиода.

Для каждого светодиода предусмотрена отдельная функция. Общая функция только последовательно вызывает их:

```c
void leds_gpio_init(void)
{
	led_1_gpio_init();
	led_2_gpio_init();
	led_3_gpio_init();
	led_4_gpio_init();
}
```

HL1 использует PORTC, остальные светодиоды — PORTA. Настройка HL4 дополнительно включает тактирование PORTF и переводит PF0 в GPIO с отключённым выходным драйвером.

## 13. Номер светодиода через enum

```c
typedef enum
{
	LED1 = 1,
	LED2 = 2,
	LED3 = 3,
	LED4 = 4
} led_t;
```

`enum` объединяет именованные значения номеров светодиодов, а `typedef` даёт типу имя `led_t`. В текущем коде этим типом объявлен параметр функций:

```c
void led_on(led_t led_number);
void led_off(led_t led_number);
```

`LED2` и `LED2_PIN` обозначают разные вещи:

- `LED2` — номер светодиода HL2, равный 2.
- `LED2_PIN` — номер линии PA3 внутри порта, равный 3.
- `LED2_MASK` — маска этой линии, равная `0x08`.

Использование `led_t` делает назначение параметра понятнее. В языке C оно не означает автоматическую проверку принадлежности каждого переданного значения перечислению во время выполнения, поэтому в `switch` предусмотрен `default`.

## 14. Выбор светодиода через switch

Включение и выключение вынесены из основного цикла в функции с параметром. Например, функция включения:

```c
void led_on(led_t led_number)
{
	switch (led_number)
	{
		case LED1:
			PORTC_RXTX |= LED1_MASK;
			break;

		case LED2:
			PORTA_RXTX |= LED2_MASK;
			break;

		case LED3:
			PORTA_RXTX |= LED3_MASK;
			break;

		case LED4:
			PORTA_RXTX |= LED4_MASK;
			break;

		default:
			break;
	}
}
```

`switch` выбирает ветвь по номеру светодиода. Каждая ветвь обращается к нужному порту и маске. `break` завершает выбранную ветвь, чтобы выполнение не перешло в следующий `case`. При неизвестном номере `default` ничего не меняет.

Функция `led_off()` устроена аналогично, но вместо установки бита выполняет его сброс через `&= ~`.

```c
led_on(LED1);
led_off(LED1);
```

Имена макросов `LED1_*`, `LED2_*`, `LED3_*`, `LED4_*` позволяют сразу увидеть, к какому светодиоду относится настройка.

## 15. Почему в примере нет static у функций

По принятому для этого занятия решению функции объявлены без `static`. Объявления функций светодиодов находятся в `leds.h`, а определения — в `leds.c`, поэтому их можно вызывать из других `.c`-файлов, подключив соответствующий заголовок.

Если бы функция на уровне файла была объявлена с `static`, её имя было бы доступно только внутри данной единицы трансляции. Это отдельное свойство связывания функций в C; в текущем примере такое ограничение не используется.

## 16. Программная задержка и приватный define

```c
#define BLINK_DELAY_ITERATIONS 400000UL
```

Этот макрос находится в `main.c`, поскольку задаёт поведение учебного приложения, а не электрическую конфигурацию светодиодов.

Здесь слово «приватный» означает расположение определения внутри `.c`-файла: другие независимо компилируемые `.c`-файлы не получают этот макрос через общий заголовок. Для этого не нужен отдельный модификатор доступа.

```c
void delay_loop(uint32_t iterations)
{
	for (volatile uint32_t counter = 0U; counter < iterations; ++counter)
	{
		continue;
	}
}
```

`iterations` — число итераций, а не число микросекунд, миллисекунд или тактов процессора. Время ожидания зависит от частоты ядра, компилятора, настроек оптимизации и сгенерированных инструкций. Во время ожидания процессор занят этим циклом.

`volatile` у счётчика нужен по другой причине, чем у аппаратного регистра: он сохраняет обращения к счётчику при оптимизации, не позволяя свести такой цикл к отсутствию действий. Точную длительность это не задаёт.

`continue` переходит к следующему шагу цикла `for`, то есть к увеличению счётчика и очередной проверке условия. В данном цикле он не добавляет полезного действия: тело можно оставить пустым, а обращения к `volatile`-счётчику останутся в управляющих выражениях цикла.

Чтобы изменить скорость мигания, меняют `BLINK_DELAY_ITERATIONS`. Для разной длительности свечения и паузы в два вызова задержки можно передавать разные количества итераций.

## 17. Что можно будет добавить в registers.h

Сейчас `registers.h` содержит общий макрос `REG32` и подключение `<stdint.h>`. Он не содержит адресов конкретного порта и не зависит от назначения выводов платы.

При реальной необходимости сюда можно добавить общие средства формирования масок и изменения полей. Доступ шириной 8 или 16 бит имеет смысл добавлять только для оборудования и регистров, которые допускают такие обращения.

Обсуждавшиеся макросы `SET_BIT` и `RESET_BIT` можно будет разместить здесь позже. Для них предполагается передача регистра и маски, а не номера бита; несколько масок можно объединять через побитовое ИЛИ. В текущие исходники эти макросы не добавлены: операции остаются явно записанными через `|=` и `&= ~`.

Для макросов приняты имена `SET_BIT` и `RESET_BIT`, для возможных функций — `set_bit` и `reset_bit`.

Адреса GPIO остаются в `gpio.h`, определения другой периферии смогут появляться в её профильных заголовках, а привязка светодиодов к выводам остаётся в `leds.h`.

## 18. Что выполняется до main

Для запуска приложения нужен стартовый код: таблица векторов, начальное значение указателя стека и обработчик сброса. Стартовая последовательность передаёт управление среде выполнения C, которая подготавливает данные программы и вызывает `main()`. В типовом варианте также вызывается функция первоначальной настройки системы `SystemInit()`.

Начальная системная настройка может влиять на частоту ядра и, следовательно, на длительность программной задержки. Сами функции управления светодиодами частоту ядра не перенастраивают.
