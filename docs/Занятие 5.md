# Занятие 5. Структуры, перечисления, объединения и преобразования типов

На прошлом занятии мы изучили указатели и научились изменять объекты через их адреса. Сегодня создадим собственные составные типы данных, разделим программу на несколько файлов, познакомимся с перечислениями и объединениями, а также разберём правила преобразования типов.

## Структуры

**Структура** объединяет несколько связанных значений, которые могут иметь разные типы. Например, точка на плоскости состоит из двух координат:

```c
struct Point {
    double x;
    double y;
};
```

`Point` после ключевого слова `struct` называется **тегом структуры**. После такого объявления тип записывается как `struct Point`:

```c
struct Point point;
```

Объявление типа само по себе не создаёт объект и не выделяет память для его полей. Память появляется при объявлении конкретной переменной.

### Объявление структуры и объекта одной конструкцией

После закрывающей фигурной скобки можно сразу перечислить создаваемые объекты:

```c
struct Point {
    double x;
    double y;
} first_point, second_point;
```

Здесь `struct Point` — тип, а `first_point` и `second_point` — переменные этого типа.

Следующая запись также допустима:

```c
struct Point {
    double x;
    double y;
} Point;
```

Но последнее имя `Point` здесь является **переменной**, а не именем типа. Такая запись выглядит двусмысленно для человека: имя с заглавной буквы похоже на название типа. Поэтому переменные будем называть в `snake_case`, а имена пользовательских типов — в `PascalCase`.

### Объявление через `typedef`

Чтобы не писать ключевое слово `struct` при каждом использовании, создадим дополнительное имя типа:

```c
typedef struct Point {
    double x;
    double y;
} Point;
```

В этой записи:

- `struct Point` — тип с тегом `Point`;
- поля `x` и `y` описывают содержимое структуры;
- последний `Point` — новое имя типа, созданное через `typedef`.

Теперь объекты можно объявлять короче:

```c
Point first_point;
Point second_point;
```

На занятии будем использовать именно форму `typedef struct TypeName { ... } TypeName`.

Анонимный вариант тоже существует:

```c
typedef struct {
    double x;
    double y;
} Point;
```

Однако именованный тег удобнее для предварительных объявлений, диагностики компилятора и типов, которые должны ссылаться сами на себя.

## Создание и инициализация объектов

Поля можно заполнить после объявления:

```c
Point point;

point.x = 10.0;
point.y = 20.0;
```

Оператор `.` выбирает поле объекта структуры.

Позиционная инициализация использует порядок полей:

```c
Point point = {10.0, 20.0};
```

Именованная инициализация явно указывает заполняемые поля:

```c
Point point = {
    .y = 20.0,
	.x = 10.0
};
```

Именованная форма лучше читается и меньше зависит от порядка полей в структуре.

## Структуры и указатели

Указатель на структуру объявляется так же, как указатель на обычный тип:

```c
Point point = {
    .x = 10.0,
    .y = 20.0
};

Point *point_pointer = &point;
```

Получить поле через разыменованный указатель можно выражением:

```c
(*point_pointer).x
```

Скобки обязательны, потому что оператор `.` имеет более высокий приоритет, чем оператор `*`.

Оператор `->` является более удобной записью той же операции:

```c
point_pointer->x
```

Выражения эквивалентны:

```c
point_pointer->x
(*point_pointer).x
```

## Передача структуры в функцию

Как и другие параметры, структура может передаваться по значению. Функция получает копию объекта:

```c
double calculate_distance_from_origin(Point point){
    return sqrt(point.x * point.x + point.y * point.y);
}
```

Изменение полей локальной копии не изменит исходный объект.

Чтобы функция изменила исходную структуру, передадим указатель:

```c
void move_point(Point *point, double dx, double dy){
    point->x += dx;
    point->y += dy;
}
```

Вызов:

```c
move_point(&point, 5.0, -2.0);
```

Если функция только читает структуру, указатель можно сделать указателем на константный объект:

```c
void print_point(const Point *point){
    printf("(%.2f, %.2f)\n", point->x, point->y);
}
```

`const` запрещает функции изменять объект через этот указатель.

Структуру можно присвоить другой переменной того же типа:

```c
Point copy = point;
```

Все поля будут скопированы. При этом язык Си не позволяет сравнивать две структуры оператором `==`: необходимые поля сравнивают отдельно или создают специальную функцию.

## Разделение программы на несколько файлов

Для работы с точками разделим программу на интерфейс, реализацию и пользовательский код:

```text
point_example/
├── point.h
├── point.c
└── main.c
```

- `point.h` содержит публичное объявление типа и прототипы функций;
- `point.c` содержит реализации операций над точками;
- `main.c` использует готовый интерфейс модуля.

`main.c` не должен подключать `point.c`. Исходные файлы компилируются отдельно, после чего их объектные файлы связываются в одну программу. В исходный код подключают заголовочные файлы.

### Заголовочный файл `point.h`

```c
#ifndef POINT_H
#define POINT_H


typedef struct Point {
    double x;
    double y;
} Point;


Point create_point(double x, double y);
void move_point(Point *point, double dx, double dy);
double calculate_distance(Point first, Point second);
void print_point(const Point *point);


#endif /* POINT_H */
```

Конструкции `#ifndef`, `#define` и `#endif` образуют **защиту заголовочного файла**, или header guard.

При первом подключении `POINT_H` ещё не определён, поэтому содержимое файла обрабатывается, после чего макрос `POINT_H` определяется. При повторном подключении условие `#ifndef POINT_H` становится ложным, и содержимое второй раз не обрабатывается.

Имя защитного макроса должно быть уникальным. Обычно его составляют из имени файла в верхнем регистре с заменой точки на подчёркивание.

### Файл реализации `point.c`

```c
#include "point.h"

#include <math.h>
#include <stdio.h>


Point create_point(double x, double y){
    Point point = {
        .x = x,
        .y = y
    };

    return point;
}


void move_point(Point *point, double dx, double dy){
    point->x += dx;
    point->y += dy;
}


double calculate_distance(Point first, Point second){
    double dx = second.x - first.x;
    double dy = second.y - first.y;

    return sqrt(dx * dx + dy * dy);
}


void print_point(const Point *point){
    printf("(%.2f, %.2f)\n", point->x, point->y);
}
```

Подключение собственного заголовочного файла первым помогает обнаруживать отсутствующие зависимости и несоответствия между прототипами и реализациями.

### Файл `main.c`

```c
#include <stdio.h>

#include "point.h"


int main(){
    Point first = create_point(1.0, 2.0);
    Point second = create_point(4.0, 6.0);

    printf("First point: ");
    print_point(&first);

    printf("Second point: ");
    print_point(&second);

    printf("Distance: %.2f\n", calculate_distance(first, second));

    move_point(&first, 2.0, -1.0);

    printf("Moved first point: ");
    print_point(&first);

    return 0;
}
```

Пример команды сборки GCC:

```text
gcc main.c point.c -o point_example -lm
```

Ключ `-lm` подключает математическую библиотеку на системах, где она требуется отдельно.

## Векторы

Более сложный пример структуры — двумерный вектор:

```c
typedef struct Vector {
    double x;
    double y;
} Vector;
```

Точка описывает положение, а вектор — направление и величину перемещения. Координаты вектора от точки `start` к точке `end` вычисляются как разность координат точек.

Добавим два файла:

```text
point_example/
├── point.h
├── point.c
├── vector.h
├── vector.c
└── main.c
```

### Заголовочный файл `vector.h`

```c
#ifndef VECTOR_H
#define VECTOR_H

#include "point.h"


typedef struct Vector {
    double x;
    double y;
} Vector;


Vector create_vector(Point start, Point end);
Vector add_vectors(Vector first, Vector second);
Vector scale_vector(Vector vector, double coefficient);
double calculate_vector_length(Vector vector);
double calculate_dot_product(Vector first, Vector second);
double calculate_cross_product(Vector first, Vector second);
void print_vector(const Vector *vector);


#endif /* VECTOR_H */
```

`vector.h` подключает `point.h`, потому что прототип функции `create_vector` использует тип `Point`.

### Файл реализации `vector.c`

```c
#include "vector.h"

#include <math.h>
#include <stdio.h>


Vector create_vector(Point start, Point end){
    Vector vector = {
        .x = end.x - start.x,
        .y = end.y - start.y
    };

    return vector;
}


Vector add_vectors(Vector first, Vector second){
    Vector result = {
        .x = first.x + second.x,
        .y = first.y + second.y
    };

    return result;
}


Vector scale_vector(Vector vector, double coefficient){
    Vector result = {
        .x = vector.x * coefficient,
        .y = vector.y * coefficient
    };

    return result;
}


double calculate_vector_length(Vector vector){
    return sqrt(vector.x * vector.x + vector.y * vector.y);
}


double calculate_dot_product(Vector first, Vector second){
    return first.x * second.x + first.y * second.y;
}


double calculate_cross_product(Vector first, Vector second){
    return first.x * second.y - first.y * second.x;
}


void print_vector(const Vector *vector){
    printf("(%.2f, %.2f)\n", vector->x, vector->y);
}
```

Для двумерных векторов функция `calculate_cross_product` возвращает одно число — ориентированную площадь параллелограмма, построенного на двух векторах. Знак результата показывает взаимную ориентацию векторов.

### Использование векторов

```c
Point first = create_point(1.0, 2.0);
Point second = create_point(4.0, 6.0);

Vector direction = create_vector(first, second);
Vector scaled = scale_vector(direction, 2.0);

printf("Direction: ");
print_vector(&direction);

printf("Length: %.2f\n", calculate_vector_length(direction));

printf("Scaled vector: ");
print_vector(&scaled);
```

Для сборки программы с двумя модулями нужно передать компилятору оба файла реализации:

```text
gcc main.c point.c vector.c -o vector_example -lm
```

## Перечисления

**Перечисление** задаёт именованный набор целочисленных констант. Оно удобно, когда значение должно обозначать одно из нескольких известных состояний.

```c
typedef enum TrafficLightState {
    TRAFFIC_LIGHT_STATE_RED,
    TRAFFIC_LIGHT_STATE_YELLOW,
    TRAFFIC_LIGHT_STATE_GREEN
} TrafficLightState;
```

Если значения не указаны явно, первая константа получает значение `0`, а каждая следующая — значение на единицу больше:

```text
TRAFFIC_LIGHT_STATE_RED    = 0
TRAFFIC_LIGHT_STATE_YELLOW = 1
TRAFFIC_LIGHT_STATE_GREEN  = 2
```

Компилятор использует эти численные значения вместо имён констант. Имена делают код понятнее, чем числа `0`, `1` и `2`.

Значения можно назначить явно:

```c
typedef enum TrafficLightState {
    TRAFFIC_LIGHT_STATE_RED = 10,
    TRAFFIC_LIGHT_STATE_YELLOW = 20,
    TRAFFIC_LIGHT_STATE_GREEN = 30
} TrafficLightState;
```

Если явно задано только одно значение, дальнейшая нумерация продолжается от него:

```c
typedef enum ExampleState {
    EXAMPLE_STATE_FIRST = 5,
    EXAMPLE_STATE_SECOND,
    EXAMPLE_STATE_THIRD
} ExampleState;
```

Здесь значения равны `5`, `6` и `7`.

Префикс `TRAFFIC_LIGHT_STATE_` уменьшает вероятность конфликта имён, потому что константы перечисления не создают отдельное пространство имён для каждого `enum`.

Не следует предполагать, что `sizeof(TrafficLightState)` всегда равен `sizeof(int)`. Компилятор выбирает совместимый целочисленный тип, способный представить все значения перечисления.

### Пример работы со светофором

```c
#include <stdio.h>


typedef enum TrafficLightState {
    TRAFFIC_LIGHT_STATE_RED,
    TRAFFIC_LIGHT_STATE_YELLOW,
    TRAFFIC_LIGHT_STATE_GREEN
} TrafficLightState;


TrafficLightState get_next_state(TrafficLightState state);
void print_state(TrafficLightState state);


int main(){
    TrafficLightState state = TRAFFIC_LIGHT_STATE_RED;

    for (int index = 0; index < 6; index++){
        print_state(state);
        state = get_next_state(state);
    }

    return 0;
}


TrafficLightState get_next_state(TrafficLightState state){
    switch (state){
        case TRAFFIC_LIGHT_STATE_RED:
            return TRAFFIC_LIGHT_STATE_GREEN;

        case TRAFFIC_LIGHT_STATE_GREEN:
            return TRAFFIC_LIGHT_STATE_YELLOW;

        case TRAFFIC_LIGHT_STATE_YELLOW:
            return TRAFFIC_LIGHT_STATE_RED;

        default:
            return TRAFFIC_LIGHT_STATE_RED;
    }
}


void print_state(TrafficLightState state){
    switch (state){
        case TRAFFIC_LIGHT_STATE_RED:
            printf("Red\n");
            break;

        case TRAFFIC_LIGHT_STATE_YELLOW:
            printf("Yellow\n");
            break;

        case TRAFFIC_LIGHT_STATE_GREEN:
            printf("Green\n");
            break;

        default:
            printf("Unknown state\n");
            break;
    }
}
```

## Преобразования типов

Преобразование типа создаёт значение одного типа на основе значения другого типа. Оно может происходить автоматически или задаваться явно.

### Неявные преобразования

Компилятор автоматически преобразует `int` в `double`, если это требуется выражением:

```c
int count = 5;
double result = count;
```

После преобразования `result` содержит `5.0`.

Преобразование результата не изменяет операции, которые уже были выполнены:

```c
int sum = 7;
int count = 2;
double average = sum / count;
```

Оба операнда деления имеют тип `int`, поэтому сначала выполняется целочисленное деление `7 / 2` и получается `3`. Только после этого число преобразуется в `double`, поэтому `average` содержит `3.0`.

### Явные преобразования

Явное преобразование записывается как имя типа в круглых скобках:

```c
double average = (double)sum / count;
```

Теперь `sum` преобразуется в `double` до деления. Второй операнд также преобразуется в `double`, и результат равен `3.5`.

### Преобразование вещественного числа в целое

```c
double source = 12.75;
int result = (int)source;
```

Дробная часть отбрасывается, поэтому `result` равен `12`. Округление до ближайшего целого не выполняется.

Если вещественное значение не представимо целевым целочисленным типом, поведение не определено. Перед таким преобразованием необходимо проверить диапазон.

### Целочисленные продвижения

В арифметических выражениях значения типов `char` и `short` обычно сначала продвигаются до `int`:

```c
unsigned char first = 200;
unsigned char second = 50;

int result = first + second;
```

Сложение выполняется не в `unsigned char`, а после продвижения операндов.

### Знаковые и беззнаковые типы

Совместное использование знаковых и беззнаковых значений может дать неожиданный результат:

```c
int signed_value = -1;
unsigned int unsigned_value = 1u;

if (signed_value < unsigned_value){
    printf("Signed value is smaller\n");
}
```

При обычных правилах преобразования `signed_value` может быть преобразован в `unsigned int`, и отрицательное число станет большим положительным значением. Поэтому условие, которое кажется очевидным человеку, может оказаться ложным.

### Перечисление и целое число

Пользовательский ввод сначала удобно считать в переменную типа `int`, проверить, а затем преобразовать:

```c
int input;

scanf("%d", &input);

if (input >= TRAFFIC_LIGHT_STATE_RED && input <= TRAFFIC_LIGHT_STATE_GREEN){
    TrafficLightState state = (TrafficLightState)input;
    print_state(state);
}
else{
    printf("Incorrect state\n");
}
```

Само преобразование не проверяет, соответствует ли число одному из объявленных элементов перечисления.

### Преобразования указателей

В языке Си указатель на объект можно неявно преобразовать в `void *` и обратно:

```c
int number = 10;
int *number_pointer = &number;
void *generic_pointer = number_pointer;
int *restored_pointer = generic_pointer;
```

`void *` хранит адрес объекта, но не содержит информации о типе находящегося там значения. Перед разыменованием необходимо восстановить правильный тип указателя.

Преобразование адреса в произвольный несовместимый тип указателя не превращает объект в значение нового типа. Разыменование такого указателя может нарушить требования выравнивания и правила доступа к объектам.

Не следует убирать `const` приведением типа, чтобы изменить объект, который был объявлен константным.

### Что нельзя преобразовать обычным cast

Разные структуры нельзя преобразовывать друг в друга, даже если они содержат одинаковые поля:

```c
typedef struct FirstPoint {
    double x;
    double y;
} FirstPoint;


typedef struct SecondPoint {
    double x;
    double y;
} SecondPoint;
```

`FirstPoint` и `SecondPoint` являются разными типами. Для переноса данных нужно явно скопировать поля или создать функцию преобразования.

## Объединения

**Объединение**, или `union`, похоже на структуру, но все его поля используют одну и ту же область памяти.

```c
typedef union NumberRepresentation {
    uint64_t unsigned_value;
    int64_t signed_value;
    float float_value;
} NumberRepresentation;
```

Схематично память объединения выглядит так:

```text
+---------------------------------------------------------------+
| Общая область памяти                                          |
+---------------------------------------------------------------+
| uint64_t unsigned_value                                       |
+---------------------------------------------------------------+
| int64_t signed_value                                          |
+-------------------------------+-------------------------------+
| float float_value             | остальная часть общей памяти  |
+-------------------------------+-------------------------------+
```

Поля структуры располагаются последовательно, а поля объединения начинаются с одного адреса. Размер объединения достаточен для хранения самого большого поля и может дополнительно учитывать требования выравнивания.

Для этого объединения на распространённых платформах `sizeof(NumberRepresentation)` равен `8`, но программа не должна считать это универсальным правилом без проверки.

### Общие адреса полей

```c
NumberRepresentation number;

printf("union:   %p\n", (void *)&number);
printf("uint64:  %p\n", (void *)&number.unsigned_value);
printf("int64:   %p\n", (void *)&number.signed_value);
printf("float:   %p\n", (void *)&number.float_value);
```

Адреса всех полей совпадут с адресом самого объединения.

### Интерпретация одной памяти разными типами

Запишем значение через поле `signed_value`, а прочитаем общую память через все три поля:

```c
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>


typedef union NumberRepresentation {
    uint64_t unsigned_value;
    int64_t signed_value;
    float float_value;
} NumberRepresentation;


int main(){
    NumberRepresentation number;

    number.signed_value = 1065353216;

    printf("Size:     %zu\n", sizeof(number));
    printf("int64_t:  %" PRId64 "\n", number.signed_value);
    printf("uint64_t: %" PRIu64 "\n", number.unsigned_value);
    printf("float:    %f\n", number.float_value);

    printf("union address:  %p\n", (void *)&number);
    printf("uint64 address: %p\n", (void *)&number.unsigned_value);
    printf("int64 address:  %p\n", (void *)&number.signed_value);
    printf("float address:  %p\n", (void *)&number.float_value);

    return 0;
}
```

На распространённой little-endian системе с 64-битными целыми типами и форматом IEEE 754 вероятен такой результат:

```text
Size:     8
int64_t:  1065353216
uint64_t: 1065353216
float:    1.000000
```

Число `1065353216` можно записать в шестнадцатеричной форме:

```text
0x000000003F800000
```

При порядке байтов little-endian оно располагается в памяти так:

```text
Меньший адрес                                      Больший адрес
     ↓                                                   ↓
+------+------+------+------+------+------+------+------+
| 00   | 00   | 80   | 3F   | 00   | 00   | 00   | 00   |
+------+------+------+------+------+------+------+------+
|<------ первые четыре байта ------>|
```

Поле `float_value` занимает первые четыре байта. Последовательность битов `0x3F800000` соответствует числу `1.0` в формате IEEE 754.

Результат зависит от порядка байтов, представления вещественных чисел, представления целых типов и поведения реализации языка Си. На другой платформе поле `float_value` может дать другое значение.

Этот пример демонстрирует общую память объединения, но не является обычным преобразованием типа. При настоящем преобразовании числового значения результат был бы другим:

```c
float converted_value = (float)number.signed_value;
```

Здесь `converted_value` будет приблизительно равен `1065353216.0f`, а не `1.0f`.

Объединение не хранит информацию о том, через какое поле было записано значение. В прикладной программе необходимо самостоятельно знать, какое поле содержит актуальные данные. На занятии ограничимся приведённым экспериментом и не будем строить дополнительные типы на основе `union`.
